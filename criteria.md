# Acceptance criteria — FitFindr

Five criteria that say what "working" means for this agent, written in unit 3
**before** any results existed.

An acceptance criterion names a target: a number, a count, a rate, or something
a person could plainly observe. *"The agent handles errors"* is an opinion.
*"When search returns nothing, the agent stops before calling the second tool,
in 5 of 5 tries"* is a criterion.

Under each one, write a sentence or two on **why that target** and not a
stricter one. A reason that says something about your tools, your loop, or the
data earns credit; *"80% seemed reasonable"* does not.

> Missing your own targets next unit costs you nothing. Setting a target so
> easy you can't miss it does.

**Two are written for you. You write three.**

---

## 1. A matching query completes all three tools

Given a query that matches at least one listing, the agent completes all three
tool calls and returns a fit card — in at least 4 of 5 tries.

**Why this target:**
I chose 4 out of 5 because `search_listings` uses keyword matching, so some valid phrasings may not match the wording in the listings exactly. The agent should still complete the full tool sequence most of the time.

---

## 2. An impossible query stops before the second tool

Given a query that matches no listings, the agent stops before calling
`suggest_outfit` and returns a message naming what to change — 5 of 5 tries.

**Why this target:**
I chose 5 out of 5 because the empty-search branch is deterministic. If no listings are returned, the agent should always stop before calling `suggest_outfit` and give the user a useful next step.

---

## 3. The same item moves through session state

Given a matching query, the `id` of `session["selected_item"]` matches the `id` of the `new_item` passed into `suggest_outfit` in 5 of 5 tries.

**Why this target:**
I used the listing ID instead of the title because two listings could potentially have the same name. The ID identifies the exact listing. I chose 5 out of 5 because state transfer is deterministic and should not randomly change between runs.

---

## 4. The fit card includes the important listing details

Given a successful run, the fit card mentions the selected item, its price, and its platform in at least 4 of 5 tries.

**Why this target:**
The fit card can use different wording because it is generated by a model, but it should still include the important facts about the thrift find. I chose 4 out of 5 because model-generated text can vary between runs, so I want a strong target without requiring the exact same output every time.

---

## 5. The search respects the user's maximum price

Given a query with a maximum price, every listing returned by `search_listings` is at or below that maximum price in 5 of 5 tries.

**Why this target:**
The maximum price is a direct filter, so the search should never return an item over the user's budget. I chose 5 out of 5 because this check is deterministic and does not depend on model-generated output.
